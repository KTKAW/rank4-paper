REPRODUCING THE PRIVATE DRAFT
Run commands from the repository root unless a different directory is shown.

1. Classifier and finite certificates
Use CPython 3.9.6 for the measured environment; the classifier needs only the
standard library and supports Python 3.9 or later.

  python3 scripts/verify.py
  python3 scripts/census.py
  python3 scripts/verify.py
  python3 scripts/finite_table.py

The independent checker has its own dense matrix mutation, permutation,
acyclicity, proper-order and transport routines. It enumerates 15,625 tuples
and replays 695 certificates. It checks finite exclusions and the small
height-proof core separately. Parametric checks have finite stated ranges;
these are transcription/regression evidence, not universal proof.

CLI examples:
  python3 -m algorithm.classifier --format tuple '[-2,0,2,-2,0,-2]'
  python3 -m algorithm.classifier --format tuple '[-2,-1,1,-1,2,-1]'
  python3 -m algorithm.classifier --format tuple '[-2,1003,1001,-1001,-999,0]' --no-shortcuts --max-states 100
The last call exits with code 2 and label UNKNOWN. This is an expected cap,
not a negative classification. Invalid inputs raise ValueError. Successful
MA and NMA diagnostic calls exit with code 0. Vertex labels start at zero.

2. Experiments
Saved evidence is immutable for the draft commit: inputs.json, raw.jsonl and
environment.json. There are 64 inputs x 2 methods x 3 repetitions. Re-running
run.py overwrites those files, so use a separate checkout/copy for new runs.

  python3 experiments/run.py
  python3 scripts/verify.py
  python3.12 -m venv environment/.venv
  environment/.venv/bin/python -m pip install -r environment/plot-requirements.txt
  environment/.venv/bin/python experiments/summarize.py

The runner fixes the seed at 20261009 and saves every generated tuple. The
summarizer creates summary.csv, statistics.json, paper/results.tex, and the
PDF/PNG performance figure from raw.jsonl. Exact deterministic results and
counters should agree when the same branches finish; timing and which cap
is encountered can vary by platform. The saved state-capped calls were all
UNKNOWN in every repetition. Current hardware values in the metadata were
read on the same host after the benchmark, because its first sandboxed
sysctl call returned unavailable. This metadata amendment changed no timing.

3. Lean: clean source build
Install elan and the toolchain specified by lean/lean-toolchain. From lean/:

  lake exe cache get
  lake build

The committed manifest locks mathlib and every transitive package. Do not
run lake update. The configured single library owns every project namespace and selects
the six entry modules with globs, recursively building their dependencies. Package caches
are external dependencies; no project .olean files are shipped.

For an explicit sequential project build with per-module logs and hashes,
after fetching the dependencies return to the repository root and run:

  python3 scripts/check_lean.py --full --lean "$(command -v lean)"

This uses lean/.lake/packages/*/.lake/build/lib/lean for external objects,
compiles all 573 project modules in manifest order into lean/.fresh-full,
and records docs/checks/lean_full/report.json. --external DIR can be repeated
to specify external dependency library paths manually. A clean full build
may require substantial time and memory, especially finite kernel proofs.
The complete project source build has NOT been performed for this draft.

Fresh checks actually performed:
  docs/checks/lean_focused/report.json: six affected modules, all successful.
  docs/checks/lean_assembly/report.json: three assembly modules, successful.
  Both use Lean 4.24.0, --trust=0 -j1, with reused imported project objects.
  Logs and resolved object hashes distinguish them from a clean full build.
  The focused closure has 216 project modules and excludes both assemblies
  named ClassificationCompletion and BoundedClassificationCompletion.

The default and --assembly replay modes of check_lean.py are local audit
conveniences: they explicitly reference the supplied research cache tree,
which is not part of this repository. Use --full on another machine. The
source assembly script package_lean.py is likewise historical provenance,
not a prerequisite for reproducing this already assembled repository.

4. Manuscript and Overleaf
  latexmk -pdf -interaction=nonstopmode -halt-on-error -cd paper/main.tex
Or run pdflatex on main.tex three times from paper/. All generated table and
figure inputs are supplied. No external bibliography processor is required.

  python3 scripts/release.py

The release script compiles the current sources, packages only the files
needed by Overleaf, extracts that archive into a fresh temporary directory,
and compiles it there. It records source hashes, PDF hashes and checks for
undefined references and overfull boxes. Upload output/rank4-overleaf.zip as
an Overleaf project, choose main.tex and pdfLaTeX, and compile. This creates
no shared account project and sends no invitations. The user requested this
upload-ready fallback rather than direct Overleaf account sharing.
